- Open the learning page, the private pilot and the local synthetic example.
  Save or print the five activity cards below and a blank feedback sheet.
- Rehearse one normal request, one unclear request and one unsupported request.
  Test microphone permissions while present if using native Voice. If it fails,

## Fit the day

Use arrival and setup from 08:30 to test the facilitator screen. Hacking runs
from 10:30 to 12:30. Give teams an initial ten-minute demonstration, then let
them choose an activity and work on their own idea. Use the final fifteen minutes
before lunch to check a result and prepare three slides or a simple webpage.
Presentations begin at 13:20 and last five minutes per team.

## Five activity cards

### 1. Hello World: a park in a file

**Ask:** “What is inside this made-up park file?”

Use the learning page's synthetic GeoJSON example. Find the name, shape and
coordinates. A point marks one position. Longitude says how far east or west;
latitude says how far north or south. This point is invented and is not a real
park record.

**Make:** a short programme or webpage that displays the name and a sentence
explaining its source. Change the made-up name and predict what changes.

**Check:** can another student tell which part is a fact from the file and which
part your team wrote? What happens if a coordinate is missing?

### 2. Reimagining services: find the right place

**Ask:** “There are two places with the same name. How do I choose?”

Use prepared place candidates or a bounded open-data pilot query operated by
the facilitator. A name can belong to a town, station or other feature. A result
list is not proof that every relevant place has been found.

**Make:** a simple webpage that lets a person choose a place and explains each
choice in plain language. This is a service-design exercise, not a DVLA address
check or connection to DVLA systems.

**Check:** does it ask for a useful extra detail when the request is unclear?
Can it work without a map or colour?

### 3. Be a data detective

**Ask:** “Who made this? When? Does it answer our question?”

Choose a source card. Find its publisher, date, licence and limits. Metadata is
information about data. An evidence receipt records what was used; it does not
make the source automatically true or suitable.

**Make:** a source label for the team's webpage using those four facts.

**Check:** can someone follow it back to the source? Does the date describe when
the data was collected, published or downloaded?

### 4. Help without jargon

**Ask:** “Explain that word so someone new can join in.”

Choose a term such as dataset, API, coordinate or boundary. An API is a way for
programmes to request information using agreed questions and answers.

**Make:** one short explanation and an example next to the relevant button or
result on the team's webpage. Let a partner rewrite it in their own words.

**Check:** can your partner complete the step without extra explanation? Leave
the original technical term available for people who need it.

### 5. Catch an overconfident answer

**Ask:** “Does a UK-wide price index tell me prices in my street?”

It does not establish that. A useful system explains the gap and suggests what
evidence would be needed. Compare a good refusal with a made-up local number.

**Make:** a helpful “we do not know yet” state for the team's webpage.

**Check:** does it explain what is missing and give a practical next step?

## Five-minute presentation

1. One minute: who needs help, and with what?
2. Two minutes: show a working example or paper prototype.
3. One minute: show the source and explain one new word.
4. One minute: show a confusing case or limitation and the improvement you made.

## Anonymous feedback sheet

Record the activity and example identifier, not a student name. Use a team code
only if the organiser approves. Do not record audio or personal free text.

| Observation | Record |
| --- | --- |
| Could the team start? | Independently / one hint / repeated help / not completed |
| Could they explain the new word? | In their own words / partly / not yet |
| Could they find the source and its limit? | Yes / partly / no |
| What confused them? | Interface or terminology issue, with no personal details |
| What should change? | One concrete improvement |
| Time to useful result | Optional stopwatch observation; do not imply a service guarantee |

This is a formative activity, not a score for a student's ability. Report counts,
observed problems and changes made. A small event cannot establish universal
accessibility or population-level success rates.
