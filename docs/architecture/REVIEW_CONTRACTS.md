## CT-01 — stale inactive wording obscures the implemented local boundary

- Priority: P2 (documentation/maintainability); confidence: high.
- Evidence: [selection result schema description](https://github.com/chris-page-gov/gis-ai-go/blob/97bc45635a91064cd78f06bf0848ad7636f05439/schemas/selection-resolve-result.schema.json#L5) says it is inactive and not an advertised transport; [query parameter schema description](https://github.com/chris-page-gov/gis-ai-go/blob/97bc45635a91064cd78f06bf0848ad7636f05439/schemas/data-query-parameters.schema.json#L5) calls the application seam inactive. The [OpenAPI/MCP projection](https://github.com/chris-page-gov/gis-ai-go/blob/97bc45635a91064cd78f06bf0848ad7636f05439/apps/mcp-gateway/src/openapi.ts#L641) exports these operation schemas, and the [governed assembly](https://github.com/chris-page-gov/gis-ai-go/blob/97bc45635a91064cd78f06bf0848ad7636f05439/apps/mcp-gateway/src/governed-assembly.ts#L59) supplies the separately admitted exact-five local/candidate profile.
- Impact: readers can mistake an implemented local contract for unused/dead code, or interpret candidate availability as public activation. There is no observed runtime failure from prose alone.
- Recommendation: revise maintained schema descriptions around the precise local/candidate boundary and keep explicit public-registration limitations. Keep discriminator/constants and historical research evidence unchanged. This review documents the distinction rather than modifying contract bytes, which can affect pinned schema digests.
- Validation for future change: find all pinned schema hashes/projections, update only intended current assertions and run contract/SDK parity and qualification digest checks. Do not blindly regenerate historic acceptance evidence.

## CT-02 — intake schema descriptors have no identified automated parity gate

- Priority: P2 (contract drift risk); confidence: high for reference/CI gap, no functional mismatch claimed.
- Evidence: the [package README](https://github.com/chris-page-gov/gis-ai-go/blob/97bc45635a91064cd78f06bf0848ad7636f05439/packages/experience-intake/README.md#L32) publishes [request](https://github.com/chris-page-gov/gis-ai-go/blob/97bc45635a91064cd78f06bf0848ad7636f05439/packages/experience-intake/schema/request.v1.schema.json#L1) and [result](https://github.com/chris-page-gov/gis-ai-go/blob/97bc45635a91064cd78f06bf0848ad7636f05439/packages/experience-intake/schema/result.v1.schema.json#L1) contracts. The [root schema catalogue checker](https://github.com/chris-page-gov/gis-ai-go/blob/97bc45635a91064cd78f06bf0848ad7636f05439/scripts/validate_contracts.py#L182) scans only `ROOT / schemas`; its fixture registry also scans that directory. [Intake tests](https://github.com/chris-page-gov/gis-ai-go/blob/97bc45635a91064cd78f06bf0848ad7636f05439/packages/experience-intake/test/intake.test.ts#L1) test the handwritten planner and malformed cases directly. No maintained executable source references either standalone intake schema filename or loads these files dynamically in the inspected package/tests.
- Impact: the local planner can remain well tested while a published descriptor drifts. Structural bounds and runtime byte/path/preview rules intentionally differ; that is not itself a bug.
- Recommendation: add a bounded descriptor check to the package assurance path: validate the two schema definitions, validate representative real planner outputs, and distinguish schema-level invalidity from the intentionally stricter runtime semantics. Keep the local planner's independent safety checks.
- Validation for future change: run the existing intake negative tests and the new producer-output/schema conformance cases. Do not count TypeScript compilation as JSON validation.

## Coverage and limitations

The immutable inventory enumerates all 102 root JSON Schemas, 13 package/OKF+/vendor JSON Schemas, 469 exported TypeScript interface/type definitions (438 project-authored and 31 vendored), 21 non-test Python dataclasses, 116 embedded definition/registration sites, the gateway OpenAPI template/projection, private execution projection and pilot SQL storage constraints. It records exact source SHA-256 values and literal consumer/reference evidence; every linked line belongs to the baseline Git tree. Root registry/fixture mappings, shared catalogue/execution types, catalogue normalisation, runtime provider/receipt semantics and local intake schema publication were inspected for documentation accuracy. Sources and contracts are catalogued, not presumed reachable because their filenames occur in code.

No contract was proved safe to delete. Six promoted version-0 governance definitions, the old evidence-inspection operation result union, host-qualification versions and private execution contracts have retained documentation/assurance/compatibility roles. Execution TypeScript interfaces are consumed by the gateway envelope builder/parser, and catalogue types are consumed by Explorer/gateway runtime code. No schema/runtime functional mismatch in those shared package types was confirmed.

Files produced: `docs/architecture/CONTRACTS.md`, `docs/architecture/CONTRACT_REGISTER.md`, `docs/architecture/contracts.json`, `scripts/build_architecture_contract_inventory.py`. The generated JSON/register can be checked using `python scripts/build_architecture_contract_inventory.py --check`. The beginner examples were evaluated using JSON Schema Draft 2020-12: valid search, empty search and actual query fixture pass; oversized limit, unknown URL and all-zero idempotency key fail; eleven query terms pass the structural schema as documented and are rejected by the application guard linked in the guide.
