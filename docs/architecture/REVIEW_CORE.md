# Core/package/execution review findings

Baseline: `97bc45635a91064cd78f06bf0848ad7636f05439`.
Ownership: packages except `experience-intake`; deterministic Python service. Catalogue implementation details were coordinated with the contract-catalogue reviewer, who confirmed schema/type consumers. Every owned source was inventoried and reference-reviewed; deep reading concentrated on contract entry points, receipt builders, publication/lookup/recovery state machines, provider execution/admission/cache and Python execution/HTTP. Supporting validation helpers in large modules received targeted reading, not an exhaustive line audit. No provider egress or deployment was performed.

## CR-03 — Evidence persistence and versioned validation modules need smaller semantic boundaries (P2 maintainability, high confidence)

The checkpoint file is 2,530 baseline lines. It contains safe filesystem access, inventory traversal, manifest validation, a hard-link publication transaction, stopped-writer orchestration and restore ([inventory L787-L882](https://github.com/chris-page-gov/gis-ai-go/blob/97bc45635a91064cd78f06bf0848ad7636f05439/packages/evidence/src/checkpoint.ts#L787-L882), [publication L1561-L1718](https://github.com/chris-page-gov/gis-ai-go/blob/97bc45635a91064cd78f06bf0848ad7636f05439/packages/evidence/src/checkpoint.ts#L1561-L1718), [creation L2110-L2251](https://github.com/chris-page-gov/gis-ai-go/blob/97bc45635a91064cd78f06bf0848ad7636f05439/packages/evidence/src/checkpoint.ts#L2110-L2251), [restore L2444-L2530](https://github.com/chris-page-gov/gis-ai-go/blob/97bc45635a91064cd78f06bf0848ad7636f05439/packages/evidence/src/checkpoint.ts#L2444-L2530)). Receipt v1/v2 also combine authority/policy/resource declarations, low-level predicates, semantic result validation and receipt construction; v2 is 2,045 lines ([public-read-receipt L617-L919](https://github.com/chris-page-gov/gis-ai-go/blob/97bc45635a91064cd78f06bf0848ad7636f05439/packages/evidence/src/public-read-receipt.ts#L617-L919), [L1444-L1618](https://github.com/chris-page-gov/gis-ai-go/blob/97bc45635a91064cd78f06bf0848ad7636f05439/packages/evidence/src/public-read-receipt.ts#L1444-L1618)).

Impact: reviewing a local storage or contract change requires navigating several distinct protocols; generic-looking duplicated validators invite accidental cross-version widening. Recommendation: extract private modules by semantic responsibility (inventory, publication state machine, checkpoint orchestration; family-local identity/result validators), keep stable exported façades, byte-identical canonical identities and exception mappings. Do not prematurely merge family-specific checks into a universal validator. Required tests: canonical receipt golden/mutation vectors, all checkpoint crash/publication tests, corruption/replay/retention/mode regressions and independent recovery verification. No behaviour refactor performed here.

## CR-04 — ONS adapter mixes transport execution, process admission and outage capabilities (P2 maintainability, high confidence)

[ons-data-api.ts L152-L233](https://github.com/chris-page-gov/gis-ai-go/blob/97bc45635a91064cd78f06bf0848ad7636f05439/packages/provider-adapter-sdk/src/ons-data-api.ts#L152-L233) owns shared call/attempt admission; [L497-L668](https://github.com/chris-page-gov/gis-ai-go/blob/97bc45635a91064cd78f06bf0848ad7636f05439/packages/provider-adapter-sdk/src/ons-data-api.ts#L497-L668) validates provider data and decompresses it; [L932-L1043](https://github.com/chris-page-gov/gis-ai-go/blob/97bc45635a91064cd78f06bf0848ad7636f05439/packages/provider-adapter-sdk/src/ons-data-api.ts#L932-L1043) performs execution/retry; [L1101-L1363](https://github.com/chris-page-gov/gis-ai-go/blob/97bc45635a91064cd78f06bf0848ad7636f05439/packages/provider-adapter-sdk/src/ons-data-api.ts#L1101-L1363) implements pristine-identity checks, reservations and one-shot outage proofs. These responsibilities share module-private brands, so naïve extraction could weaken provenance checks.

Impact: difficult review of resource-lifetime and one-shot-consumption guarantees. Do not replace branded outage proof with caller-supplied JSON.

## CR-05 — Dense CPIH transactional statements obscure all-or-none invariants (P2 maintainability, high confidence)

[web216-transactional-contract.ts L193-L223](https://github.com/chris-page-gov/gis-ai-go/blob/97bc45635a91064cd78f06bf0848ad7636f05439/packages/evidence/src/web216-transactional-contract.ts#L193-L223) compresses snapshot validation, chronology, uniqueness, expected-record regeneration and head reconstruction into long compound predicates and multiple statements per line. [web216-transactional-d1.ts L130-L170](https://github.com/chris-page-gov/gis-ai-go/blob/97bc45635a91064cd78f06bf0848ad7636f05439/packages/evidence/src/web216-transactional-d1.ts#L130-L170) similarly compresses cancellation, conditional write and read-back outcomes.

Impact: hard to identify which check prevents a forged plan, stale update or success after an uncertain write. Recommendation: first reformat without semantic changes; then consider named family-specific predicates for record equality, chronology and write acknowledgement. Preserve the distinction between pure model transitions and observed persistence. Required tests: concurrent heads, copied plans, changed store/software, corruption, lost acknowledgements, read-back failure and post-write abort (existing tests already name these cases). Documentation adds the CAS pre/postconditions; no code reformat performed.

## CR-06 — Canonical-number implementations require explicit parity maintenance (P3, medium confidence, improvement not a demonstrated defect)

Python [canonical.py L52-L104](https://github.com/chris-page-gov/gis-ai-go/blob/97bc45635a91064cd78f06bf0848ad7636f05439/services/geo-execution/src/gis_ai_go_execution/canonical.py#L52-L104) manually converts Python float representations to ECMAScript-style canonical numbers; TypeScript delegates finite-number spelling to [JSON.stringify L180-L189](https://github.com/chris-page-gov/gis-ai-go/blob/97bc45635a91064cd78f06bf0848ad7636f05439/packages/evidence/src/canonical-json.ts#L180-L189). Existing [cross-language vectors L141-L167](https://github.com/chris-page-gov/gis-ai-go/blob/97bc45635a91064cd78f06bf0848ad7636f05439/services/geo-execution/tests/test_service.py#L141-L167) cover negative zero, selected exponent transitions, a decimal and Unicode. No incorrect canonical result was established in this review.

Impact: contract drift between independent languages would change evidence hashes while both implementations still typecheck. Recommendation: keep independent runtime checks but maintain one data-driven accepted/rejected parity corpus including numeric boundary/rounding, UTF-16 key ordering, depth and malformed-key cases. Required tests: both implementations must consume identical corpus and produce identical canonical bytes/digests where their accepted subsets intersect. Do not replace the independent Python validation with trust in gateway validation.

- Versioned receipt validators: legacy byte identity and compatibility boundaries, not safe duplicate-code deletions.
- Independent Python request validation and TypeScript declarations: cross-service defence and language boundary, not redundant checks.
