# Experimental and metadata review findings

Baseline: `97bc45635a91064cd78f06bf0848ad7636f05439`.
Follow-up: EX-07 is addressed in [the validation repair record](../implementation/VALIDATION_REPAIRS.md).
The findings below retain their original source baseline and references.

The review makes no behavioural changes, removals or refactors. It adds an architecture chapter and comments in six source files. All seven findings below have high confidence in the identified code pattern; impact is maintainability/conditional risk rather than a demonstrated production incident. Suggested priority: EX-01 P3, EX-02 P2, EX-03 P3, EX-04 P2, EX-05 P3, EX-06 P3, EX-07 P2.

Consumer evidence: local/hosted CPIH factories are called from explicit HTTP/workbench assembly and their own tests; `package_sites_pilot_runtime.mjs` bundles both pilot source modules; `sites/private-pilot/server/sites-pilot-runtime.mjs` shares them across `/mcp` and `/pilot/mcp`. OKF+ `build.py` is called by package scripts, verification subprocesses, and synthetic relocated-build tests; `validate_record` reads the mutable module `ROOT`. The local `key` declaration has no read anywhere in its module and is not exported; shared inputs are its actual replacement. `experience_evaluate.mjs` is invoked by package.json and imported by tests, so its string extractors are active CI dependencies. Missing-schema fallback is an explicit synthetic-fixture convenience used by production code, not a report of missing current schema files.


The review found one definite dead module-local value and several maintainability issues. No public export or experimental entrypoint is classified as dead merely because the default production gateway does not mount it. Test-only injection seams and pinned vendored consumers also have real uses.
